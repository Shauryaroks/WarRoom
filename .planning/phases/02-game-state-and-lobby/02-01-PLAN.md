    ```python
    import logging
    import redis
    from app.worker.celery_app import celery_app

    logger = logging.getLogger(__name__)

    REDIS_GAME_STATUS_KEY = "game:status"

    def is_game_active() -> bool:
        """Check Redis for current game status. Returns True only if ACTIVE.
        Per D-09: Redis key check for ~1ms latency vs ~5ms DB query."""
        r = redis.from_url(celery_app.conf.broker_url)
        try:
            status = r.get(REDIS_GAME_STATUS_KEY)
            if status is None:
                return False
            if isinstance(status, bytes):
                status = status.decode()
            return status == "ACTIVE"
        finally:
            r.close()

    @celery_app.task(name="game.tick")
    def game_tick():
        """Periodic tick task. Guarded by game state check (GAME-04).
        Phase 2: just the guard + logging. Phase 3: stock price updates."""
        if not is_game_active():
            return  # Silent return -- game not active, no work to do
        logger.info("game.tick executed (game is ACTIVE)")
        # Phase 3 will add: stock price calculation, broadcast
    ```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client -> Admin API | Untrusted HTTP requests to game control endpoints. Must verify admin role. |
| Redis cache | Internal Docker network only. Celery workers trust Redis game:status value. |
| WebSocket broadcast | Server pushes state to all clients. Clients cannot modify game state via WebSocket. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Elevation of Privilege | POST /admin/game/start,pause,resume | mitigate | All game control endpoints use `require_admin` FastAPI dependency which verifies JWT role="admin" claim [VERIFIED: auth_utils.py] |
| T-02-02 | Tampering | State transitions | mitigate | `VALID_TRANSITIONS` dict rejects invalid transitions server-side; SELECT FOR UPDATE prevents concurrent transition race conditions |
| T-02-03 | Tampering | Timer manipulation | mitigate | D-07: Timer is server-authoritative. Client receives elapsed_seconds via WebSocket, never computes locally. No client input affects timer. |
| T-02-04 | Tampering | Redis game:status key | accept | Redis is internal to Docker network, not exposed externally. If Redis is compromised, attacker has broader access anyway. |
| T-02-05 | Denial of Service | Rapid start/pause/resume clicks | mitigate | SELECT FOR UPDATE serializes concurrent transitions. Each transition is a single DB row update -- minimal load. |
| T-02-06 | Information Disclosure | GET /admin/game/state | mitigate | Endpoint requires admin auth. Non-admin users receive game state only via WebSocket broadcast (public information by design). |
</threat_model>
