# Phase 1 -- UI Design Contract

> Visual and interaction contract for Phase 1: Foundation, Auth, and Base UI. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn (initialize during implementation) |
| Preset | Custom dark preset -- configure after `npx shadcn init` with neutral base, dark mode default, no border-radius on data panels |
| Component library | Radix UI (via shadcn) |
| Icon library | lucide-react |
| Fonts | Inter (UI labels/body), JetBrains Mono (data/numbers/tickers) |

**shadcn initialization notes:** When the Next.js app is scaffolded, run `npx shadcn@latest init` with:
- Style: Default
- Base color: Neutral
- CSS variables: Yes
- Override `--radius` to `0.375rem` (6px) for form inputs, `0` for data panels

**Phase 1 shadcn components to install:** `button`, `input`, `label`, `card`, `badge`, `separator`, `sonner` (toast notifications)

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding between label and icon |
| sm | 8px | Compact element spacing, form field gaps, table cell padding |
| md | 16px | Default element spacing, card padding, input padding |
| lg | 24px | Section padding within cards, form section breaks |
| xl | 32px | Layout gaps between major panels |
| 2xl | 48px | Page-level vertical padding (auth pages centered card offset) |
| 3xl | 64px | Auth page top margin from viewport edge |

Exceptions: none

## Typography

| Role | Size | Weight | Line Height | Font Family |
|------|------|--------|-------------|-------------|
| Body | 14px | 400 (regular) | 1.5 | Inter |
| Label | 12px | 400 (regular) | 1.4 | Inter |
| Heading | 20px | 600 (semibold) | 1.2 | Inter |
| Data | 14px | 400 (regular) | 1.4 | JetBrains Mono |
| Data Large | 20px | 600 (semibold) | 1.2 | JetBrains Mono |
| Ticker | 14px | 600 (semibold) | 1.0 | JetBrains Mono |

**Font loading:** Load Inter and JetBrains Mono via `next/font/google`. Use `font-display: swap` for both. Assign CSS custom properties:
- `--font-sans: Inter` (applied to body)
- `--font-mono: JetBrains Mono` (applied via `font-mono` Tailwind class)

**Rules:**
- All stock prices, percentages, ticker symbols, and numerical data use `font-mono`
- All UI labels, descriptions, headings, and body text use the sans-serif stack
- Never mix: a single text element uses one font family only

### Accent Colors (10% combined)

| Color | Hex | Reserved For |
|-------|-----|--------------|
| Amber | `#FF9500` | Primary CTA buttons, active tab indicators, focused input rings, "LIVE" status badge |
| Green | `#00C853` | Success toasts, "approved" badges, "connected" status indicator, positive stock movement (future phases) |

- Green and Red are semantic only -- never used for primary actions
- Blue is for navigation links and informational elements only
- No color is used purely for decoration

## Page Contracts

### 1. Register Page (`/auth/register`)

**Layout:** Centered single card on full-viewport dark background. Card max-width 420px. Vertically centered with 3xl top offset on large screens, centered with auto margins on smaller.

**Elements:**
| Element | Spec |
|---------|------|
| Logo/Brand | "COMPLEX" in JetBrains Mono, 20px semibold, amber color, top of card |
| Subtitle | "Case Competition Platform" in Inter, 12px, text-secondary, below logo |
| Team Name input | Label "Team Name", placeholder "e.g. Apex Capital" |
| Ticker input | Label "Ticker Symbol", placeholder "e.g. APEX", auto-uppercase, max 5 chars, min 3 chars |
| Email input | Label "Email", type email, placeholder "team@example.com" |
| Password input | Label "Password", type password, min 8 chars |
| Submit button | "Register Team" -- amber background, dark text, full width |
| Login link | "Already registered? Log in" -- "Log in" portion is blue link |
| Validation | Inline below each field in red, 12px. Ticker must be 3-5 uppercase alpha only. |

**States:**
- Default: All fields empty, button enabled
- Validating: Client-side validation on blur for each field
- Submitting: Button shows "Registering..." with disabled state, reduced opacity
- Success: Toast (sonner) "Team registered. Awaiting admin approval." -- green accent
- Error (duplicate ticker): Inline error under ticker field "Ticker already taken"
- Error (duplicate email): Inline error under email field "Email already registered"
- Error (server): Toast "Registration failed. Try again." -- red accent

### 2. Login Page (`/auth/login`)

**Layout:** Same centered card as Register, max-width 420px.

**Elements:**
| Element | Spec |
|---------|------|
| Logo/Brand | Same as register |
| Subtitle | Same as register |
| Email input | Label "Email", type email |
| Password input | Label "Password", type password |
| Role selector | Two-option toggle: "Strategist" / "Trader". Default: Strategist. Styled as segmented control -- selected option has amber background with dark text, unselected has surface background with secondary text. |
| Submit button | "Log In" -- amber background, dark text, full width |
| Register link | "No team yet? Register" -- "Register" is blue link |

**States:**
- Default: Fields empty, Strategist selected, button enabled
- Submitting: Button shows "Logging in..." with disabled state
- Success: Redirect to `/lobby` (or `/game` if game is active)
- Error (bad credentials): Toast "Invalid email or password." -- red accent
- Error (not approved): Toast "Team not yet approved by admin." -- amber accent
- Error (server): Toast "Login failed. Try again." -- red accent

### 3. Admin Login Page (`/admin/login`)

**Layout:** Same centered card, max-width 380px. No role selector.

**Elements:**
| Element | Spec |
|---------|------|
| Logo/Brand | "COMPLEX" same style |
| Subtitle | "Admin Panel" in Inter, 12px, text-secondary |
| Email input | Label "Email" |
| Password input | Label "Password" |
| Submit button | "Access Panel" -- amber background, dark text, full width |

**States:**
- Same as team login minus role selector and registration link
- Error (not admin): Toast "Access denied." -- red accent

### 4. Lobby Page (`/lobby`)

**Layout:** Full viewport dark background. Centered content area, max-width 600px. Two visual sections stacked vertically.

**Elements:**
| Element | Spec |
|---------|------|
| Team identity | Team name in 20px semibold Inter + Ticker in 14px bold JetBrains Mono amber, separated by `8px` gap |
| Status badge | "WAITING" -- amber text on amber/10% background, 12px mono, with pulsing dot animation (CSS `@keyframes pulse` on a 6px amber circle) |
| Waiting message | "Waiting for admin to start the game..." in 14px Inter, text-secondary |
| Approved teams list | Section heading "Teams" in 12px medium Inter, text-secondary, uppercase tracking-wider. Each team row: ticker (mono, amber) + team name (Inter, primary text). Rows separated by border-bottom #2A2A2A. |
| Connection indicator | Bottom-left fixed: green dot + "Connected" in 12px mono text-secondary. If disconnected: red dot + "Reconnecting..." |
| Logout | Top-right: "Log out" text button in text-secondary, hover text-primary |

**States:**
- Connected + waiting: Default state, pulsing dot, team list populating via WebSocket
- Team joins: New row animates in (fade + slide down, 200ms ease-out)
- Game starting: Status badge changes to "STARTING" green, then redirect to `/game` after 1 second
- Disconnected: Connection indicator switches to red "Reconnecting...", overlay does NOT block the page (non-intrusive)
- Empty teams list: "No teams approved yet" in text-secondary, centered in list area

## Interaction Patterns

### Form Validation
- Validate on blur (not on keystroke)
- Show inline error below the offending field in red 12px text
- Clear inline error when the user modifies the field value
- Server-side errors (duplicate ticker/email) display inline under the relevant field, not as toasts
- Network/server errors display as toasts via sonner

### Loading States
- Buttons: Text changes to gerund form ("Registering...", "Logging in..."), opacity reduced to 0.7, pointer-events disabled
- No skeleton screens in Phase 1 (pages are simple enough to not need them)
- Lobby team list: no loading spinner -- list starts empty and populates via WebSocket events

### Transitions
- Page transitions: none (standard Next.js navigation)
- Lobby team join: `opacity 0 -> 1` + `translateY(-8px) -> 0` over 200ms ease-out
- Status badge pulse: `@keyframes pulse` -- amber dot scales 1.0 to 1.4 and opacity 1.0 to 0.4 over 1.5s infinite

### Toast Notifications
- Position: top-right
- Duration: 4 seconds for success, 5 seconds for errors
- Style: dark surface background (#1E1E1E), border #333333, left accent stripe (4px) in semantic color (green/red/amber)
- Dismissible by click

## Design Decisions Log

| Decision | Source | Rationale |
|----------|--------|-----------|
| shadcn/ui over pure Tailwind | D-06 (Claude's discretion) | Bloomberg density requires many form primitives; shadcn provides accessible, unstyled Radix components that match the "functional, no decorative" mandate. Saves significant time on auth forms. |
| Inter + JetBrains Mono dual font | STITCH_PROMPT.md | Bloomberg Terminal convention: monospace for data, sans-serif for UI. JetBrains Mono has excellent legibility at small sizes for tabular data. |
| No border-radius on data panels, 6px on form inputs | STITCH_PROMPT.md ("No rounded corners on data panels") | Auth form inputs get subtle rounding for usability. Data-dense panels (lobby team list, future game panels) use sharp corners for Bloomberg aesthetic. |
| Amber as sole primary action color | STITCH_PROMPT.md | Bloomberg Terminal uses amber/orange for primary highlights. Green/Red reserved for semantic meaning (up/down, success/error). |
| No skeleton screens in Phase 1 | Phase scope | Auth pages and lobby are simple enough that loading states are handled by button text changes and WebSocket-driven list population. |
| Toast position top-right | Convention | Avoids obscuring centered auth forms. Top-right is standard for notification toasts. |
